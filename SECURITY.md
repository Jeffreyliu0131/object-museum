# Security Policy

Object Museum is a browser-local portfolio prototype. It is not a production
service, backup system, private archive, compliance control, or privacy
guarantee.

## Supported versions

Security fixes are considered for the current default branch only. No tagged
version is currently designated as a supported production release.

## Report a vulnerability privately

Before this repository is made public, the maintainer must enable GitHub
Private Vulnerability Reporting and verify the link below. The link is a
publication gate, not a claim that the unpublished repository is currently
reachable.

Use this repository's
[private GitHub Security Advisory
form](https://github.com/Jeffreyliu0131/object-museum/security/advisories/new):

1. Open the private advisory form.
2. Select **Report a vulnerability**.
3. Submit the details below.

Do not disclose a suspected vulnerability in a public issue, discussion, pull
request, commit, or social post. If private vulnerability reporting is not
available, open the [private-contact request
form](https://github.com/Jeffreyliu0131/object-museum/issues/new?template=private_contact.yml)
without sharing any vulnerability, exploit, incident, or affected-person
details. A maintainer must enable or provide a private route before details are
submitted.

Include:

- the affected commit, version, browser, and operating system;
- the vulnerability class and plausible impact;
- minimal reproduction steps using synthetic placeholder data only;
- relevant, sanitized logs or screenshots;
- whether the issue is already public; and
- a suggested mitigation, if known.

## Data safety

Never send real family, household, personal, confidential, or identifying data
in a security report. Do not include names, faces, voices, stories, contact
details, locations, credentials, tokens, private documents, or media metadata.
Use the repository's synthetic fixtures or newly invented placeholders.

Do not access another person's data, degrade third-party services, use social
engineering, or perform destructive testing. Stop testing if there is a risk of
data exposure or loss.

## Response and disclosure

Maintainers handle reports on a best-effort basis and do not promise a response
or remediation SLA. They will aim to acknowledge the report, validate scope,
coordinate a fix, and publish an advisory when appropriate. Keep the report
confidential until the maintainers agree that coordinated disclosure is safe.

Reports about general support, feature requests, or known non-security
limitations should follow [SUPPORT.md](SUPPORT.md).
