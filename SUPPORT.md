# Support

Object Museum is maintained as a local portfolio and learning prototype. It has
no hosted service, production operations, account recovery, backup/restore,
external data processing, or guaranteed support SLA.

## Before asking for help

Read:

- [README.md](README.md) for setup and verification;
- [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md) for intentional boundaries;
- [DATA_PRIVACY.md](DATA_PRIVACY.md) for local storage and data handling; and
- [EXPERIENCE_ACCEPTANCE.md](EXPERIENCE_ACCEPTANCE.md) for the walkthrough.

Use the bug report form for a reproducible defect and the feature request form
for a scoped proposal. If the documentation is unclear, file a feature request
that identifies the specific page and missing explanation.

Security vulnerabilities must be reported privately through GitHub Security
Advisories as described in [SECURITY.md](SECURITY.md). If that route is not
available, the public private-contact request form may be used only to ask for
a private route, never to disclose vulnerability details. Do not report a
vulnerability in any other issue or pull request.

## Public data boundary

Never submit real family, household, personal, confidential, or identifying
data in a support request. Do not attach private photos, voices, stories,
contact details, locations, credentials, documents, database contents, or raw
logs. Use synthetic placeholders and sanitize screenshots, logs, filenames, and
metadata before posting.

Maintainers may close requests that are out of scope, cannot be reproduced, ask
for production or legal assurances, or expose private information. Responses
are best effort and depend on maintainer availability.
